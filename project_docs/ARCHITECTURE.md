# J.A.R.V.I.S. Technical Architecture

## 1. Conversational Intelligence Layer

### Unified Brain Memory (`ThreadManager.ts` & `memory.ts`)
J.A.R.V.I.S. operates on a single, omnipresent consciousness that spans across all interfaces (Web Chat, Web Voice, Telegram Chat, Telegram Voice).
- **Global Session Memory**: All Telegram bot interactions instantly sync to `session_memory.json`, allowing the Browser Voice UI (Zoya) to retain full context of mobile conversations.
- **Unified Thread ID**: Web Chat dynamically maps its thread identifier to `tg_${adminChatId}` (the user's cached Telegram Chat ID), merging both chat environments into the exact same persistent file (`data/threads/{threadId}.json`).

### Knowledge Base RAG (`knowledgeManager.ts`)
J.A.R.V.I.S. features long-term semantic memory for facts, documents, and notes, separate from chat history.
- **pgvector Integration**: Uses Supabase pgvector to store 768-dimensional embeddings generated by Gemini.
- **Universal Tooling**: Exposes `save_knowledge` and `search_knowledge` tools to all interfaces (Web, Telegram, Voice).
- **Semantic Matching**: Uses the `match_knowledge` RPC function for cosine similarity matching, allowing Jarvis to instantly recall stored knowledge when asked "what do you know about X".

### Model Context Protocol (`mcpManager.ts`)
J.A.R.V.I.S. supports the MCP standard to dynamically connect to external tool servers without writing custom code.
- **Dynamic Tool Discovery**: On startup, `McpManager.initialize()` reads `data/mcp_config.json` and spawns MCP servers as child processes over `stdio`.
- **Universal Execution**: Any tool returned by an MCP server is automatically available to Jarvis. If Jarvis calls a tool whose name begins with `mcp_`, the execution fallback fires in `api.ts`, `websocket.ts`, and `telegramBot.ts`.
- **Zero-Cost**: MCP servers run locally on the Render dyno as child processes — no paid API calls required.
- **UI Management**: A dedicated `McpSettings` tab in the web UI allows adding, viewing, and removing integrations at runtime (e.g., GitHub, Filesystem, Brave Search) without any code changes.

### Modular Prompt Assembly (`prompt_builder.ts`)
The system uses a **"Soul vs. Skills"** architecture for system instructions.
- **Soul (`personality.json`)**: Defines the core identity (JARVIS, aristocratic, concise, Nepali-mirroring). Shared by ALL agents.
- **Skills (`voice_skills.json`, `tools_browser.json`, etc.)**: Adds capabilities specific to the medium (e.g., emotion tags for voice, DOM selectors for browser).
- **Integration**: The `buildPrompt()` function dynamically assembles these modules into a single optimized system instruction.

## 2. Neural Sync Bridge

### Shared Context API
The Frontend (Zoya Gemini Live) and Backend (Node.js/Telegram) are now synchronized via:
- **`GET /api/config/voice-prompt`**: Dynamically pulls the "Soul" from the server to ensure personality consistency.
- **`GET /api/session-context`**: Injects shared chat/voice history (including synced Telegram interactions) into the Gemini Live session so Zoya "remembers" what was said in any medium.

## 3. Input & Orchestration

### Intent Classification (`intentClassifier.ts`)
Uses a high-speed Llama-3-8B model to route requests:
- **Direct Mode**: Conversational, tone instructions, language shifts. (Routed to `callChatWithCascade`).
- **Agent Mode**: Physical browser tasks or deep research. (Routed to `planner.ts`).

### Multilingual Transcription
The Telegram transcription engine (Whisper) is configured for **Native Nepali/English Detection**.
- **Context Hinting**: Includes `Nepali, English, JARVIS, Susant` as prompt context to Whisper to ensure high accuracy for code-switching.
- **Language Lock**: Explicitly removed forced 'en' translation to allow native Nepali text processing.

## 5. Telegram Remote Access Layer

### Telegram Web App (Mini App)
For mobile remote access, J.A.R.V.I.S. utilizes a **Telegram Web App Interface**.
- **Route**: `GET /telegram-call`
- **Bridge**: The Telegram bot provides a persistent "Call" button that opens this mobile-optimized route.
- **Voice Stack**: Integrates `ZoyaLiveService` via WebRTC/WebSockets directly inside the Telegram browser, bypassing bot-level audio limitations.
- **Aesthetics**: Automatically inherits Telegram's theme colors and expands to full-screen for an immersive 3D Avatar experience.
- **Ngrok Static Tunnels**: Uses fixed-domain ngrok tunnels to ensure the Web App URL remains persistent across restarts.

## 6. Host OS Automation (I.R.I.S. Layer)

### The J.A.R.V.I.S. - I.R.I.S. Bridge
To bypass browser-sandbox limitations, J.A.R.V.I.S. communicates with a native desktop daemon called **I.R.I.S.**.
- **J.A.R.V.I.S. (The Brain)**: Resides in the cloud or on a separate local server. It plans physical actions and formats them as strictly typed JSON payloads.
- **I.R.I.S. (The Hands)**: An Electron-based desktop app running natively on the Windows host machine. It binds directly to the OS to control the mouse, keyboard, apps, and screen.
- **The Tunnel**: I.R.I.S. establishes a Cloudflare reverse tunnel (e.g., `https://*.trycloudflare.com`) on boot. J.A.R.V.I.S. sends commands to this URL (`POST /execute`) authenticated via an `IRIS_API_KEY` bearer token.

### Execution Loop
1. Gemini LLM triggers the `execute_local_os_command` function.
2. The Node.js Web Server regex-extracts the JSON payload (to bypass conversational hallucination wrappings).
3. The payload is forwarded across the Cloudflare tunnel to I.R.I.S.
4. I.R.I.S. uses `nut-js` (clipboard typing, keys), `child_process` (PowerShell/CMD), and `desktopCapturer` (Screenshots) to perform the physical action.
5. I.R.I.S. responds with a `{ success, message }` JSON, which is passed back to Gemini's context window.

## 6. Time & Transparency Layers

### Neural Scheduler (`scheduler.ts`)
A background execution engine for time-delayed tasks.
- **Delayed Trigger Flow**: Uses high-precision Node.js `setTimeout` in-memory timers to track `delay_seconds` for future events. When the time expires, it fires a MacroDroid webhook to instantly ring the physical phone and sends a dynamic, time-aware LLM-generated briefing to Telegram.
- **Dynamic Context Briefing**: The scheduler dynamically fetches your active timezone and current time to formulate real-time, context-aware instructions for the LLM. It automatically adjusts its personality and prompts: if the task is a wake-up call, it commands you to get out of bed; if it's a general reminder (e.g. "drink water"), it prompts you to perform the task immediately.
- **Omega Watchdog Loop & Auto-Disarm**: Once triggered, J.A.R.V.I.S. checks back every 2 minutes. If the user has not interacted with Telegram, it fires the MacroDroid webhook again and sends a warning containing the exact task content. Any text or voice note sent to the Telegram bot immediately satisfies and disarms the active watchdog loop, returning early to prevent double-replies from the chat AI.
- **Dynamic Task Cancellation & Modification**: The scheduler injects active pending tasks into the LLM system prompt. The user can say "cancel my alarm" or "change my drink water alarm to a message in 2 minutes," and the scheduler will dynamically cancel, update, or reschedule tasks by their IDs.
- **Future Migration (Supabase)**: Because Render free-tier restarts wipe in-memory `setTimeout` objects, the architecture will migrate to a persistent Supabase/Postgres queue or Upstash QStash webhook trigger to ensure indestructible task scheduling.

### Deep Trace Logging
A unified diagnostic system for real-time neural observation.
- **Trace Points**: Logs intent classification (Why?), planner reasoning (How?), and tool registration (What?).
- **HUD Telemetry**: Captures exact latency in milliseconds and total token consumption for every request.
- **Lifecycle Tracking**: Monitors scheduled tasks from registration to final execution trigger.

## 7. Voice Biometrics & Security (Hugging Face Microservice)

To bypass Render's Free Tier RAM limits (512MB), avoid paid cloud APIs, and ensure J.A.R.V.I.S. works even when the user's local PC is turned off, the Voice Biometrics engine is deployed as an independent serverless microservice.

### Speaker Identification & Routing
- **Engine**: Open-source Python Audio Engine (e.g., SpeechBrain) deployed on a **Hugging Face Space** (Free Tier: 16GB RAM, 2 vCPUs).
- **Audio Interception**: Before sending audio to Whisper STT, the Render server makes a rapid API call to the Hugging Face Space with the audio chunk.
- **Authentication**: The extracted voice print is matched against a hardcoded, encrypted "Boss Profile". If it fails, the system cross-references the dynamic `voice_profiles` table in **Supabase**.
- **Dynamic Enrollment**: If the voice is completely unknown, J.A.R.V.I.S. halts the standard LLM response and triggers a specialized "Who are you?" intent to register the new speaker dynamically into Supabase.
- **Voice Profile Reconfiguration & Name Correction**: If a speaker's voice is misidentified or needs updating (e.g. "I am xyz not abc"), the `update_guest_voice` tool calls `/api/update-guest-name` to edit the profile in Supabase while enforcing immutability on Boss credentials.

### Anti-Spoofing & Target Extraction
Because the Hugging Face Space has ample RAM, we can run state-of-the-art models:
- **Liveness Detection**: Analyzes the audio for synthetic distortion to prevent playback attacks (recordings of the boss's voice).
- **Target Speaker Extraction**: If the Boss and a stranger speak simultaneously, the Hugging Face microservice filters out the stranger's voice frequencies before sending the clean audio back to the Render server.

## 7. Dual-Search Strategy
The system utilizes two distinct research engines:
1. **Gemini Grounding**: Used for conversational knowledge and deep research (Answering).
2. **DuckDuckGo/SerpAPI**: Used by the Planner for raw link extraction and browser automation (Doing).
